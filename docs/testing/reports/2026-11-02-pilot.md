## 1. Résumé et recommandation

La campagne complète a tourné de bout en bout avec `CAMPAIGN_LEVEL=full
scripts/test-pipeline.sh` : les neuf étapes sont passées au premier essai, sans
test instable, en 471 s. Après le dernier correctif (outillage des métriques),
toute la campagne a été relancée et repassée au vert en 466 s ; les chiffres
ci-dessous viennent de cette relance. Le lot a révélé cinq défauts backend (plantage du
processus sur perte de connexion, arrêt bloqué, course entre deux démarrages,
traversée de chemin à la suppression d'une pièce jointe, interblocage sur des
déplacements concurrents). Chacun est corrigé et couvert par un test de
non-régression. La couverture passe au-dessus de 90 % sur les quatre métriques,
côté backend comme frontend, et la mutation dépasse les planchers.

Recommandation : **GO**, avec les écarts de la section 7 suivis comme risques
résiduels.

## 7. Écarts au plan

- Session exploratoire : le niveau complet prévoit 60 minutes avec une charte
  écrite. Seule une session API courte a été menée. Aucun défaut, une
  observation : le titre d'une carte n'a pas de longueur maximale (10 000
  caractères acceptés).
- Rejeu des migrations sur une copie de base existante : fait hors pipeline.
  Une base construite avec le code de `main`, remplie (50 comptes, 20 tableaux,
  80 colonnes, 2 000 cartes) et ramenée à l'état d'avant la migration 005, a
  été copiée par `pg_dump`, puis ouverte deux fois avec le code du lot. Les
  cinq migrations sont marquées, `is_admin` est ajoutée à faux pour tous, et
  aucune ligne n'est perdue. Ce rejeu n'est pas encore automatisé.
- La mutation frontend de la campagne a pu réutiliser le fichier incrémental de
  Stryker. Le score complet sera confirmé par l'exécution en CI.
- npm audit remonte des alertes modérées sur `minimatch` dans l'outillage de
  développement, sans correctif publié. Elles sont sous le seuil bloquant.

## 9. Leçons apprises

- Ne jamais modifier `scripts/test-pipeline.sh` pendant qu'il tourne : bash lit
  le script au fil de l'eau et la campagne s'arrête en erreur de syntaxe.
- Les tests sur PostgreSQL réel trouvent ce que PGlite masque (verrous,
  courses au démarrage) : trois des cinq défauts viennent de là.
- La durée totale enregistrée dans l'historique est arrondie au dixième pour
  éviter le bruit des flottants dans la revue hebdomadaire.

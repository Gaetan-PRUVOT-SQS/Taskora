## 1. Résumé et recommandation

Les deux échecs CI de 5e25cac ont chacun une cause identifiée et un correctif :

- Tests unitaires : sous Node 22, trois tests de la suite « arrêt » de
  `http.test.js` étaient annulés. Ce n'était pas un défaut du test : le
  minuteur de `createShutdown` était `unref()`. Quand la fermeture attend une
  promesse qui ne tient aucune ressource, rien ne garde la boucle ouverte. En
  production, le processus sortait alors avec le code 0, sans le message
  « Arrêt trop long », à l'inverse de ce que demande `bounded-shutdown.md`.
- gitleaks : le mot de passe des comptes de test k6 était écrit en clair dans
  `test/performance/k6/board-load.js` depuis 4190194.

La campagne complète `CAMPAIGN_LEVEL=full PERF_PROFILE=load
scripts/test-pipeline.sh` a tourné deux fois sous Node 22 : à 11:53 sur l'arbre
de travail, puis à 12:07 sur 72f6c8e une fois les deux correctifs commités. Les
deux fois, les neuf étapes sont passées au premier essai, sans test instable.
Les chiffres ci-dessous viennent de la relance (675 s au total).

Recommandation : **GO**, avec les écarts de la section 7 suivis comme risques
résiduels.

## 9. Leçons apprises

- Lancer les tests sous la version de Node de `.nvmrc`, celle de la CI :
  Node 24 laisse passer une suite que Node 22 annule.
- Un `unref()` sur un minuteur de garde peut le rendre inutile : s'il est la
  seule chose qui tient la boucle ouverte, le processus sort sans lui.
- gitleaks analyse tout l'historique : un secret retiré du code reste un
  constat. Passer par une variable d'environnement et ignorer l'empreinte
  exacte, sans réécrire l'historique.
